# 使いやすさ重視レビュー / 改善バックログ

作成日: 2026-06-08
対象: Splatoon 3 ブキ縛りプラベ・ルーレット
方針: 画面共有映えより、主催者が迷わず操作できることを優先する。

## 今回の結論

前回の「発表モードで結果を大きく見せる」方向は、画面共有で見せるだけの用途には過剰。
このアプリは、主催者がプラベ進行中に使う操作盤として、以下を常に見失わない方が重要。

- 参加者数
- 抽選候補数
- 使用済み数
- 手動除外数
- 現在の縛り
- 自動使用済みON/OFF
- 今回結果
- 次に押すべきボタン

特に、抽選後に設定・候補数・ブキリストが強制的に隠れる設計は、ユーザーの最新意図と合っていない。

## 最優先で直すべき問題 P0

### P0-1. 抽選後に presentation-mode へ自動遷移しない

問題:
- 抽選完了後、左設定・右ブキリスト・ヒーロー・候補数が隠れる。
- 主催者が「今どの条件か」「使用済みがどうなったか」を確認するために毎回戻る必要がある。

改善:
- 抽選後も通常の操作画面を維持する。
- 発表モードを残すなら、明示的な「結果だけ表示」ボタンを押した時だけ入る。

受け入れ条件:
- 8人抽選後も参加者、縛り、候補数、使用済み数、結果が同じ操作画面で確認できる。
- `設定に戻る` を押さないと操作状態が見えない、という状態がなくなる。

### P0-2. ブキ種0件でも抽選できるバグを直す

問題:
- 「全ブキOFF」でブキ種をすべてOFFにしても、候補数が全ブキ相当のままになることがある。
- その状態で抽選できる場合がある。

原因候補:
- `filterWeapons()` が `enabledTypes: []` を「絞り込みなし」と扱っている。
- UI側ではブキ種0件エラーを出しているが、抽選側では候補0として扱っていない。

改善:
- `enabledTypes` が空配列なら候補0を返す。
- 抽選前にも `selectedTypes.size === 0` を明示的にブロックする。

受け入れ条件:
- ブキ種0件では候補数が0になる。
- 抽選ボタンを押しても結果・履歴・使用済みが増えない。
- エラー文: `抽選できません: ブキ種を1つ以上選んでください。`

### P0-3. 抽選中に設定を変更できないようにする

問題:
- 抽選中でも左のブキ種フィルターが操作できる。
- 抽選開始時の候補と、抽選完了時のルール表示がズレる可能性がある。

改善:
- 抽選中は参加者、ブキ種、オーダー、重複、右ブキリスト、全ON/OFFなど抽選条件をすべてdisabledにする。

受け入れ条件:
- 抽選中に変更可能な抽選条件がない。
- 完了後の結果とルール表示が一致する。

### P0-4. 抽選結果と抽選時ルールをスナップショット化する

問題:
- 抽選後に設定変更すると、コピー文が「現在のルール + 前回の結果」になる可能性がある。
- 1人用/8人用切替後も古い結果やコピーが残る。

改善:
- 抽選時点の `drawMode`, `ruleSummary`, `players`, `assignments`, `timestamp` を `latestResultMeta` として保存する。
- コピーは現在設定ではなく、抽選時スナップショットを使う。
- 設定変更後は「前回結果」扱いにするか、コピーを無効化する。

受け入れ条件:
- 抽選後にブキ種や参加者を変更しても、コピー文が不整合にならない。
- モード切替後に古い8人結果を「1ブキ抽選結果」としてコピーしない。

### P0-5. 抽選後の主操作を「採用」と「再抽選」に分ける

問題:
- `もう一度抽選` が、「今回結果を破棄して引き直す」のか「次試合を抽選する」のか分かりにくい。
- 自動使用済みONの場合、未採用の結果まで使用済み化される。

改善案:
- 抽選直後は `未採用結果` とする。
- ボタンを分ける:
  - `この結果を採用して使用済みにする`
  - `結果を破棄して再抽選`
  - `結果をコピー`
- 自動使用済みは抽選完了時ではなく、採用時に反映する。

受け入れ条件:
- 破棄した結果のブキは使用済みに入らない。
- 採用した結果だけが使用済み履歴と右ブキリストに反映される。

## 高優先 P1

### P1-1. 結果の二重表示を整理する

問題:
- 抽選後、ルーレットカード8枚と結果カード8枚が上下に重複して表示される。

改善:
- 抽選中はルーレットカード。
- 抽選後は同じエリアを「今回結果」として使い、下部結果リストは省略または折りたたみ。

受け入れ条件:
- 同じ8人結果が画面内で2セット表示されない。

### P1-2. 候補数・使用済み数・自動使用済み状態を抽選ボタン近くに出す

問題:
- 候補数が左パネル内にあり、抽選ボタンや結果から離れている。
- 発表モード中は隠れる。

改善:
- 抽選ヘッダー付近に状態チップを置く。
  - 参加者: 8人
  - 候補: 133/141
  - 使用済み: 8
  - 手動除外: 0
  - 自動使用済み: ON

受け入れ条件:
- 抽選前後のどちらでも主状態が一目で分かる。

### P1-3. 候補不足を抽選前に出す

問題:
- 8人・重複なし・候補7件などでも、押すまで候補不足が分からない。

改善:
- `updateSummary()` 時点で候補数 < 参加者数を検出する。
- 抽選ボタンをdisabledにするか、ボタン文言を `候補不足` にする。

受け入れ条件:
- 候補不足時に抽選前から警告が出る。
- 重複ありに切り替える/候補を増やすと解除される。

### P1-4. 1人用/8人用を「サンプル」だと明示する

問題:
- ボタンがモード切替なのか、参加者欄を上書きするサンプル投入なのか分かりづらい。

改善文言:
- `1人サンプル`
- `8人サンプル`
- `参加者をクリア`

受け入れ条件:
- 押すと参加者欄が変わることが分かる。
- 入力済み参加者がある時は確認またはUndoがある。

### P1-5. 左フィルターと右ブキリストの役割を分ける

問題:
- 左: ブキ種フィルター。
- 右: カテゴリごとON/OFF + 個別ON/OFF。
- どちらもON/OFFなので混同しやすい。

改善:
- 左見出し: `ブキ種で絞る`
- 右見出し: `個別ブキ除外・使用済み管理`
- 右の全操作:
  - `個別除外をすべて解除`
  - `全ブキを個別除外`

受け入れ条件:
- 左OFFカテゴリが右では「ブキ種フィルターで対象外」と分かる。
- 右リストのチェックが「個別候補ON/OFF」だと分かる。

### P1-6. エラー表示を role=alert / aria-live 対応にする

問題:
- エラーが視覚表示のみで、支援技術に通知されにくい。

改善:
- `errorBox` に `role="alert"` または `aria-live="assertive"` を付ける。
- エラー文に直し方を含める。

受け入れ条件:
- エラー発生時に支援技術へ通知される。
- 何を直せばいいか分かる。

### P1-7. フォーカス可視化を強化する

問題:
- カスタムスイッチやブキ種ピルのフォーカス位置が分かりづらい。

改善:
- `button`, `input`, `summary`, `.type-pill`, `.weapon-item` に `:focus-visible` を追加。

受け入れ条件:
- キーボードだけで現在位置が常に分かる。

## 中優先 P2

### P2-1. 共有用コピー文の末尾ネタ文を任意化する

現状:
- `文句はルーレットに言ってください。` が固定。

改善:
- デフォルトでは外す、または設定ON時だけ付ける。

### P2-2. ルールサマリーを短縮する

改善:
- 全種選択時: `対象: 全ブキ種`
- 一部選択時: `対象: 3種（シューター / ローラー / フデ）`

### P2-3. reduced motion / 演出控えめに対応する

改善:
- OSの `prefers-reduced-motion: reduce` を尊重する。
- オプションで `演出を控えめにする` を追加する。

### P2-4. 参加者入力欄に明示ラベルと区切り説明を追加する

改善文言:
- ラベル: `参加者名`
- 補足: `1行に1人ずつ入力。カンマ・読点区切りも使えます。`

### P2-5. 右/左という説明をレスポンシブ非依存にする

改善:
- `右側で...` → `ブキリストで...`
- `右リストのチェック...` → `ブキリストのチェック...`

## 推奨実装順

### 第1バッチ: 事故防止・不整合修正

1. `filterWeapons` の空配列バグ修正
2. 抽選中disabled漏れ修正
3. 抽選時スナップショット導入
4. モード/参加者/縛り変更時の古い結果扱い整理
5. 候補不足の事前検出

### 第2バッチ: ユーザーフロー修正

1. presentation-mode自動遷移をやめる
2. 採用/破棄/コピーのボタン分離
3. 使用済み反映を採用時に移す
4. 結果二重表示を整理

### 第3バッチ: 文言・アクセシビリティ

1. サンプル/クリア/全ブキON/OFF文言変更
2. errorBox aria-live対応
3. focus-visible追加
4. ルールサマリー短縮
5. reduced motion対応

## 検証観点

- `npm run build:bundle`
- `npm test`
- `node --check src/main.js`
- `node --check src/app.bundle.js`
- file:// 直接起動
- 8人抽選 → 採用 → 使用済み反映 → コピー
- 8人抽選 → 破棄して再抽選 → 未採用ブキが使用済みにならない
- 全ブキOFF → 候補0 → 抽選不可
- 抽選中にすべての抽選条件がdisabled
- 抽選後に設定変更 → 古い結果コピーが不整合にならない
- 1人用/8人用切替で古い結果が混ざらない
- 候補不足が事前表示される
- エラーが視覚・支援技術の両方に通知される
